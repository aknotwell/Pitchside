# Pitchside — Project Plan

## Context
Hackathon brief: build an AI pipeline that turns **synthetic** football events into explainable match intelligence, following five stages: **ingest → interpret → explain → render → personalize**. Also required: multi-language output, live overlays and recaps, and creating or extending synthetic datasets. No footage is provided, and real footage needs licenses, so all data is generated by us.

**Our angle:** *One match, many broadcasts.* The same live event stream produces genuinely different experiences for different viewers:
- **Casual fan:** stakes, emotion, simple stats
- **Analyst:** pressure index, PPDA, pass difficulty, momentum
- **Academy player ("Learn mode"):** coaching cues on decisions, scanning and positioning. This is our differentiator.
- **Scout:** player-focus mode that follows one player all match and produces a scouting report at full time

Each mode can be combined with a **language**, a **favorite club** and a **favorite player**.

Team: 3 people, about 2.5 weeks. Stack: Python (FastAPI) + React. LLM: local (Ollama) for now, behind a provider interface so Claude or another API can be swapped in later.

Repo state: empty apart from README.md. System Python is 3.9.6, so we'll use Python 3.11+ via `uv`. Node 26 is installed.

## Architecture

```
[1] Synthetic Match Generator ──► event stream (JSONL, timestamped, replayable at 1x–20x)
                                        │  WebSocket / in-process queue
[2] Intelligence Engine (deterministic, no LLM)
      • running match state (score, possession, phase, zones)
      • metrics: pass distance/accuracy/difficulty, ball & shot speed, xG,
        player distance & sprint speed, PPDA, pressure index, field tilt
      • pattern detectors: momentum swing, control-vs-chaos, rhythm/tempo, pressing trap
      • key-moment detector → Moment {type, importance 0–1, reasons[], evidence{stats}}
                                        │
[3] Explainer: turns reasons + evidence into a structured "why it matters" fact sheet
                                        │
[4] Narrative layer (LLM via provider interface)
      persona × language × fav club/player → commentary line, overlay text, recap
      Grounded: the LLM may only use facts from the fact sheet
      Fallback: template text if the LLM is slow or unavailable (keeps live latency low)
                                        │
[5] Render: timed overlay cues (JSON) + React broadcast UI
      • 2D animated pitch (players + ball from tracking frames)
      • overlay graphics: name tags, speed/distance badges, pass-difficulty pop-ups, momentum bar
      • 4 persona panels side by side + full-time recap
```

Key design rule: **numbers come from code, words come from the LLM.** This keeps the explanations honest and makes the local model's job small (phrasing only), which matters for speed.

## Data contracts (agree on these in Week 1, Day 1)
All modules communicate through these Pydantic schemas (`backend/pitchside/schemas.py`), mirrored as TS types in the front end.

- `MatchMeta`: teams, lineups (id, name, number, position, ratings), venue, competition
- `TrackingFrame`: `t`, ball `{x,y,z}`, players `[{id,x,y}]` at 10 fps; pitch is 105×68 m
- `Event`: `id, t, type (pass|shot|tackle|interception|carry|dribble|pressure|foul|possession_change|goal|save|card|sub|period), team, player, start{x,y}, end{x,y}, outcome, extra{}` (similar to StatsBomb)
- `Moment`: `id, t, type, importance, reasons[], evidence{}, players[]`
- `OverlayCue`: `id, t_in, t_out, slot (lower_third|tag|badge|bar|fullscreen), template, data{}, text{lang: str}`
- `ViewerProfile`: `persona, language, fav_club, fav_player, focus_metric`

`OverlayCue` is the machine-readable, timed output the brief asks for ("rendered as synchronized graphical overlays").

## Components and owners

### A. Synthetic generator (`backend/pitchside/generator/`): **Person 1**
- Agent-based sim at 10 Hz: 22 players with formation anchors, ball physics, team shape shifting with possession
- Possession state machine picks actions (pass/carry/shot/dribble) weighted by player ratings, pressure and pitch zone; outcomes are stochastic
- Emits both tracking frames and events; seeded so runs are reproducible
- Scenario scripts for demos: "late comeback", "red card chaos", "high press vs low block", "wonderkid breakout"
- Validation: compare event distributions with typical match numbers (~900 passes, ~25 shots, ~80% pass accuracy, ~105 km team distance)
- Output: `data/matches/<id>/{meta.json, events.jsonl, tracking.jsonl}` + a published dataset README (covers "data innovation")

### B. Intelligence engine + explainer (`backend/pitchside/engine/`): **Person 2**
- `state.py`: running match state; `metrics.py`: per-event and rolling metrics
- Pass difficulty = f(distance, pressure on passer, receiver marking, line-breaking, angle), from 0 to 1
- Simple xG from distance and angle; shot/ball speed from tracking
- Speed/distance threshold triggers for player tag badges (e.g. sprint > 32 km/h)
- `patterns.py`: momentum (rolling xT/possession), control-vs-chaos (turnover rate + pass-chain length), tempo, pressure shifts
- `moments.py`: importance scoring plus reasons, e.g. "first shot on target in 30 min", "3rd turnover under press this half", "milestone: 100th pass"
- Unit-tested and fully deterministic

### C. Narrative + LLM layer (`backend/pitchside/narrative/`): **Person 3**
- `providers/base.py`: `LLMProvider.generate(prompt, schema)`; implementations `ollama.py` (default, e.g. `qwen2.5:7b` or `llama3.1:8b`), `anthropic.py` (stub, ready for a key), `template.py` (no-LLM fallback). Selected by env var `PITCHSIDE_LLM`
- `personas/`: one prompt and output spec per persona (fan, analyst, academy, scout), each choosing *which* facts to use, not only tone
- Live path: only moments above an importance threshold go to the LLM; the rest use templates. Async queue with a timeout falls back to a template
- Multi-language: generated directly in the target language (start with EN, ES, FR, AR, PT); overlay text is cached per language
- Full-time recap (all personas) and scout report (player-focus) built from the whole match
- Groundedness check: every number in the output must appear in the fact sheet

### D. API + front end (`backend/pitchside/api/`, `frontend/`): **shared, led by whoever finishes first; everyone in Week 3**
- FastAPI: `POST /matches/{id}/play?speed=`, `WS /live/{match_id}?persona=&lang=&club=&player=` streaming frames, cues and commentary
- React + Vite + Tailwind: canvas pitch view, overlay layer driven by `OverlayCue` timing, profile picker, 4-panel "many broadcasts" demo view, recap screen

## Verification
- `pytest backend/tests`: schema round-trips, generator statistical sanity bands, metric unit tests (known pass → known difficulty), moment detector on scripted scenarios
- `make gen SEED=42` produces identical output twice (determinism)
- `make demo`: run a scenario at 10x; check in the browser (built-in preview) that the pitch animates, overlays appear and disappear on time, and the 4 persona panels show *different* content for the same moment
- Switch the language in the UI and confirm overlay and commentary change; set `PITCHSIDE_LLM=template` and confirm everything still works with no model running
- Latency check: event → on-screen cue < 1 s (template), < 4 s (LLM) on a laptop
